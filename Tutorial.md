# Vivado tutorial: ZCU216 from a blinking LED to a pulse generator

Three progressive projects for the Xilinx ZCU216 (Zynq UltraScale+ RFSoC, `xczu49dr-ffvf1760-2-e`),
each one Scala file, one Tcl script and one command:

| step | design      | adds                                                                 | time to bitstream (32 cores) |
|------|-------------|----------------------------------------------------------------------|------------------------------|
| 1    | `BlinkLed`  | the minimal project: PS + one SpinalHDL module + 8 LEDs             | ~5 min                        |
| 2    | `AxiLed`    | memory-mapped registers over AXI, switches and buttons              | ~5 min                        |
| 3    | `SimpleAwg` | a pulse generator on the RF data converters, 16 DACs + 16 ADCs      | ~7 min                        |

The slides for the 40-minute talk are a separate artifact; this file is the written version with
every command.

## 0. Prerequisites and layout

- Vivado 2026.1 on the `PATH` (`vivado -version`), with the ZCU216 board files (shipped with 2026.1).
- `mill` 1.1 and a JDK (SpinalHDL 1.14.2 is pulled from Maven by `build.mill`).
- On the board: PYNQ with `xrfclk` (step 3 only).

```
build.mill, .mill-version        Mill project: Scala 2.12 + SpinalHDL
src/VivadoHelper.scala            attributes that make a Verilog module a block-design citizen, ClockInterface
src/BlinkLed.scala                step 1

src/SimpleAwg.scala               step 3
fpga/src/rtl/*.v                  generated Verilog (committed so the Vivado part works without Scala)
fpga/src/constraints/*.xdc        pin and clock constraints (zcu216_reference.xdc = the board master file)

fpga/script/utils/*.tcl           shared pieces: ZynqPs, AxiSmartConnect, Rfdc, RfdcConfig, Finish
fpga/build/<Step>/                Vivado project, reports, <Step>.bit + <Step>.hwh (git-ignored)

```

Quick start for any step:

```sh

```

## 1. The pieces of a Vivado project

### 1.1 Files

- **RTL** (`fpga/src/rtl`): the circuit as text, Verilog (`.v`) or VHDL (`.vhd`). One module is the
  *top*; its ports are the pins of the design. We generate the Verilog from SpinalHDL, a Scala
  library: a design is normal code with types, loops and functions, and Vivado only ever sees the
  generated file.
- **Constraints** (`fpga/src/constraints`, `.xdc`): which package pin each top-level port uses and
  with which I/O standard, plus the period of every clock that enters the chip. The board vendor
  ships a master file with every pin of the board (`zcu216_reference.xdc`); we copy the lines we
  need and rename the ports to ours.

  ```tcl
  set_property -dict {PACKAGE_PIN AN14 IOSTANDARD LVCMOS12} [get_ports {led_r[0]}]
  create_clock -period 2.000 -name dspClk_clk_p [get_ports {dspClk_clk_p}]
  ```

  Only clocks need the second kind of constraint; without a period the tools cannot check that the
  logic is fast enough. Clocks generated by the processing system carry their own period.
- **Scripts** (`fpga/script`, `.tcl`): every click in the Vivado GUI is a Tcl command (it is echoed
  in the Tcl console), so a whole project build is a script you can replay. References:
  [UG835 Tcl command reference](https://docs.xilinx.com/r/en-US/ug835-vivado-tcl-commands),
  [BYU TclVivado wiki](https://github.com/byu-cpe/BYU-Computing-Tutorials/wiki/TclVivado),
  [Tcl tutorial](https://wiki.tcl-lang.org/page/Tcl+Tutorial+Lesson+0).

### 1.2 Block design

The processing system, resets, bus fabric and the RF data converters are Xilinx IP: configurable,
encrypted blocks we do not write. The block design (IP Integrator) is the schematic that connects
them to our module. Our Verilog enters as a *module reference* (`create_bd_cell -type module`):
Vivado parses the ports and shows the module as a block. Five verbs cover everything:

```tcl
create_bd_design bd                                                      ;# the schematic
create_bd_cell -type ip -vlnv xilinx.com:ip:zynq_ultra_ps_e:3.5 zynq_ps  ;# an IP block
create_bd_cell -type module -reference BlinkLed Top                      ;# our module
connect_bd_net [get_bd_pins zynq_ps/pl_clk0] [get_bd_pins Top/clk]       ;# a wire
create_bd_port -dir O -from 7 -to 0 led_r                                ;# a pin of the chip
connect_bd_intf_net [get_bd_intf_pins axi_smc/M00_AXI] [get_bd_intf_pins Top/S_AXI] ;# a whole bus
```

`validate_bd_design` is the compiler of the block design: it checks clock frequencies, reset
polarities, bus parameters and addresses, and is where most mistakes show up. `make_wrapper`
generates a plain Verilog top that instantiates the block design; the pin names of the chip are the
block-design port names, which is why the `.xdc` files talk about `led_r[0]` and `dspClk_clk_p`.

**Interface inference.** An AXI bus is about 40 Verilog ports. A Vivado attribute on each port
names the bus it belongs to, so the block design shows one connectable interface pin instead of 40:

```verilog
(* X_INTERFACE_INFO = "xilinx.com:interface:aximm:1.0 S_AXI AWVALID" *) input wire io_axi_aw_valid,
(* X_INTERFACE_INFO = "xilinx.com:signal:clock:1.0 clk CLK",
   X_INTERFACE_PARAMETER = "ASSOCIATED_BUSIF S_AXI, ASSOCIATED_RESET reset" *) input wire clk,
```

`src/VivadoHelper.scala` adds these from Scala: `VivadoHelper.axi4(bus, "S_AXI")`,
`VivadoHelper.axis(stream, "DAC0_AXIS")`, `VivadoHelper.clockDomain(cd, "S_AXI")`,
`VivadoHelper.clock(clk, "dspClk", rst, "dspRst", 500000000, busIfs...)`. The parameter attribute
is `X_INTERFACE_PARAMETER`, singular; the plural spelling is silently ignored by the module
reference importer (see Troubleshooting).

### 1.3 Memory map

Registers in the FPGA appear as addresses in the processor's memory. Three things must agree on
those addresses: the block design (the address editor, `assign_bd_address`), our RTL (the decoder,
`Axi4SlaveFactory`) and the software (`pynq.MMIO`). The PS master we use, `M_AXI_HPM0_LPD`, reaches
the PL from `0x8000_0000`; the slave sees the full 32-bit address, so the RTL uses the same absolute
addresses as the block design.

### 1.4 Synthesis, implementation, bitstream

- **Synthesis** (`synth_1`) turns the RTL into a netlist of things the chip has: LUTs and carry
  chains for logic, flip-flops for registers, block RAM tiles for memories, DSP48 slices for
  multipliers. Read the utilization report afterwards: it tells you whether a memory became block
  RAM or thousands of LUTs.
- **Implementation** (`impl_1`) places every cell, routes every net, and runs timing analysis:
  every register-to-register path is checked against the clock period from the constraints. The one
  number to check is the **worst negative slack** (WNS) in the timing report: positive means every
  path fits. Vivado writes the bitstream even when timing fails, so "bitstream generated" is not
  proof that the design works.
- **Bitstream** (`write_bitstream`): the configuration of every cell and switch, ~34 MB for this
  chip. PYNQ needs it next to the hardware handoff file (`.hwh`, generated with the block design)
  under the same base name: `BlinkLed.bit` + `BlinkLed.hwh`.

`fpga/script/utils/Finish.tcl` does all of this and is shared by the three steps.

## 2. Step 1: BlinkLed, the minimal project

**Design** (`src/BlinkLed.scala`): a free-running counter drives the 8 red LEDs. LED 0 toggles every
2^24 cycles of the 100 MHz PS clock (0.17 s), every next LED at half the rate.

```scala
case class BlinkLed() extends Component {
  val io = new Bundle { val led = out Bits (8 bits) }
  VivadoHelper.clockDomain(ClockDomain.current)   // marks clk/reset for the block design

  val counter = Reg(UInt(32 bits)) init 0
  counter := counter + 1
  io.led := counter(31 downto 24).asBits
}
```

SpinalHDL adds the implicit `clk` and `reset` ports (active-high, asynchronous by default).

**What it needs:** a clock (`pl_clk0`, 100 MHz, generated by the PS), a reset (`pl_resetn0`
through a `proc_sys_reset` block, which turns the asynchronous active-low PS reset into a clean
synchronous active-high one), 8 output pins, a part and a board. **What it does not need:** an
external clock pin (so no `create_clock`), a bus, software.

**Block design** (`fpga/script/BlinkLed.tcl`, `utils/ZynqPs.tcl`): three cells, four nets, one port.

```
zynq_ps.pl_clk0     -> Top.clk, ps_rst.slowest_sync_clk
zynq_ps.pl_resetn0  -> ps_rst.ext_reset_in
ps_rst.peripheral_reset -> Top.reset
Top.io_led          -> port led_r[7:0]      (zcu216-led.xdc binds it to AN14, AP16, ...)
```

`ZynqPs.tcl` creates the PS with the ZCU216 board preset (`apply_board_preset`), keeps only the
HPM0_LPD master (`PSU__USE__M_AXI_GP2`) and connects its clock. The LED pins are in 1.2 V banks
(`LVCMOS12`), the green LEDs 0..3 in a 1.8 V bank (`LVCMOS18`); the master file is the source of
truth.

**Build and result:**

```sh
mill runMain vivado.tutorial.BlinkLed
cd fpga/build && vivado -mode batch -source ../script/BlinkLed.tcl
```

| report                             | value                                    |
|------------------------------------|------------------------------------------|
| `BlinkLed/BlinkLed_utilization.rpt`| 17 LUTs, 65 registers (of 425 280 / 850 560) |
| `BlinkLed/BlinkLed_timing.rpt`     | WNS +9.100 ns on a 10 ns period          |

To look at the block design: `vivado fpga/build/BlinkLed/BlinkLed.xpr`, IP Integrator, Open Block
Design. On the board: copy `BlinkLed.bit` and `BlinkLed.hwh`, then `pynq.Overlay("BlinkLed.bit")`.

## 3. Step 2: AxiLed, memory-mapped registers

**Design** (`src/AxiLed.scala`): the same module gains an AXI4 slave, green and blue LEDs, DIP
switches and push buttons. `Axi4SlaveFactory` decodes the addresses and drives the AXI handshakes;
we never write the protocol by hand.

```scala
val io = new Bundle {
  val axi = slave(Axi4(Axi4Config(addressWidth = 32, dataWidth = 32, idWidth = 2)))
  val ledR, ledG, ledB = out Bits (8 bits)
  val dipSw = in Bits (8 bits)
  val btn = in Bits (5 bits)
}
VivadoHelper.axi4(io.axi, "S_AXI")
VivadoHelper.clockDomain(ClockDomain.current, "S_AXI")

val base = 0x80000000L
val factory = Axi4SlaveFactory(io.axi)
factory.driveAndRead(io.ledR, base + 0x00) init 0
factory.driveAndRead(io.ledG, base + 0x04) init 0
factory.driveAndRead(io.ledB, base + 0x08) init 0
factory.read(io.dipSw, base + 0x0C)
factory.read(io.btn, base + 0x10)
```

| address       | access | register                     |
|---------------|--------|------------------------------|
| `0x8000_0000` | R/W    | red LEDs, bit i = LED i      |
| `0x8000_0004` | R/W    | green LEDs                   |
| `0x8000_0008` | R/W    | blue LEDs                    |
| `0x8000_000C` | R      | DIP switches                 |
| `0x8000_0010` | R      | push buttons N, E, S, W, C   |

**AXI4 in one paragraph.** The ARM bus between a master (the PS) and slaves (our module). Five
independent channels, each a valid/ready handshake like a SpinalHDL `Stream`: AW (write address),
W (write data + byte strobes), B (write response), AR (read address), R (read data). The PS speaks
128-bit AXI with 16-bit IDs; an **AXI SmartConnect** converts to our 32-bit, 2-bit-ID slave and,
in step 3, routes to several slaves.

**Block design** (`fpga/script/AxiLed.tcl`, 14 lines more than step 1): `utils/AxiSmartConnect.tcl`
adds the SmartConnect between `zynq_ps/M_AXI_HPM0_LPD` and `Top/S_AXI`, all on `pl_clk0`; four more
ports; and the address editor entry:

```tcl
assign_bd_address -offset 0x80000000 -range 0x00010000 \
  -target_address_space [get_bd_addr_spaces zynq_ps/Data] [get_bd_addr_segs Top/S_AXI/reg0] -force
```

**Result:** 1 439 LUTs, 1 529 registers, WNS +6.093 ns. Eighty times step 1, almost all of it the
SmartConnect and PS glue, not our five registers, and still a rounding error on this chip.

**Software** (`software/axi_led_demo.py`):

```python
ol = pynq.Overlay("AxiLed.bit")           # AxiLed.hwh must sit next to it
mmio = pynq.MMIO(0x8000_0000, 0x1000)
mmio.write(0x00, 0b1010_1010)             # red LEDs
print(bin(mmio.read(0x0C)))               # DIP switches
```

## 4. Step 3: SimpleAwg, a pulse generator on the RF data converters

### 4.1 The idea

A pulse generator is a memory and a timer. Per channel:

- a **pulse memory**, 1024 × 256 bit = 16 384 DAC samples, written by the host;
- a **timer** loaded by the host with a duration in 500 MHz cycles; while it runs, an address
  counter walks the memory and one 256-bit word (16 samples) goes to the DAC every cycle, so the
  DAC runs at 8 GSPS. The address wraps at the end of the memory, so a long duration repeats the
  waveform (load one period of a sine, play for a second, look at it on a scope);
- a **record buffer**, 1024 × 64 bit = 4 096 ADC samples (4 per cycle, 2 GSPS), written while any
  channel plays and read back by the host, so a DAC cabled into an ADC can be checked from Python.

This is the datapath of RISC-Q's `SimpleAwg` (`riscq/scratch/RfTester.scala`) with plain AXI4
instead of the TileLink fabric; RISC-Q adds a processor that writes the durations with nanosecond
timing.

### 4.2 Two clock domains

| domain        | clock                           | what runs there                                   |
|---------------|---------------------------------|---------------------------------------------------|
| host, `clk`   | `pl_clk0`, 100 MHz from the PS  | AXI slave, register writes, memory writes, read-back |
| converter, `dspClk` | 500 MHz from the CLK104 board clock (LVDS pin E10/E9) | timers, memory read-out, DAC and ADC streams |

The two clocks have no phase relation, so the `.xdc` declares them asynchronous
(`set_clock_groups -asynchronous -group {dspClk_clk_p}`) and the design crosses them only with:

| what crosses               | mechanism                                            | in the code                                   |
|----------------------------|------------------------------------------------------|-----------------------------------------------|
| pulse samples, host → dsp  | dual-clock block RAM: write port on `clk`, read port on `dspClk` | `pulseMem.readSync(addr, clockCrossing = true)` |
| ADC samples, dsp → host    | dual-clock block RAM the other way round             | `recordMem.write(addr, adcWord, enable)` + `readSync(..., clockCrossing = true)` |
| the start command          | toggle synchroniser with its 32-bit payload          | `startFlow.ccToggle(hostCd, dspCd)`            |
| status bits back           | two-register synchroniser                            | `BufferCC(fire)`                               |

At 500 MHz the period is 2 ns: one block RAM read and one register per stage, nothing more. The
first build met timing by 0.020 ns because the block RAM output register fed the converter's data
input directly through 1.5 ns of routing; one extra register on each converter path
(`RegNext(RegNext(...))` on the DAC word, `RegNext(io.adc(c).payload)` before the record write)
gives the placer a flop next to the converter.

### 4.3 Memory map (`S_AXI` at `0x8000_0000`, 4 MB)

| address                        | access | meaning                                                  |
|--------------------------------|--------|----------------------------------------------------------|
| `0x8000_0000 + 4·c`            | W      | duration of channel c (0..15) in `dspClk` cycles; writing starts it |
| `0x8000_0040`                  | R      | number of 64-bit words recorded since the last start (0..1024) |
| `0x8000_0044`                  | R      | bit c = channel c is playing                             |
| `0x8010_0000 + 0x8000·c`       | W      | pulse memory c, 32 KB, int16 samples, oldest first       |
| `0x8020_0000 + 0x2000·c`       | R      | record buffer c, 8 KB, int16 samples, oldest first       |

Wide memories are reached as 32-bit words: `factory.writeMemMultiWord` turns each bus write into a
masked write of one 32-bit lane of a 256-bit word (SpinalHDL emits eight 32-bit "symbol" arrays per
memory, each one block RAM). The record buffer read is spelled out by hand because the library
helper does not know the memory is written from another clock domain.

### 4.4 The per-channel logic (`src/SimpleAwg.scala`)

```scala
val dsp = new ClockingArea(dspCd) {
  val chans = for (c <- 0 until channels) yield new Area {
    val start = starts(c).ccToggle(hostCd, dspCd)
    val timer = Reg(UInt(32 bits)) init 0
    val addr = Reg(UInt(10 bits)) init 0
    val fire = RegNext(timer =/= 0) init False
    when(start.valid) { timer := start.payload; addr := 0 }
      .elsewhen(timer =/= 0) { timer := timer - 1 }
    when(fire) { addr := addr + 1 }
    val sample = pulseMems(c).readSync(addr, clockCrossing = true)       // 1 cycle after addr
    io.dac(c).payload := RegNext(RegNext(Mux(RegNext(fire), sample, B(0, 256 bits))))
  }
  val anyFire = RegNext(chans.map(_.fire).orR) init False
  val recAddr = Reg(UInt(11 bits)) init 1024                               // bit 10 set = full
  val recording = anyFire && !recAddr.msb
  when(anyStart) { recAddr := 0 } elsewhen (recording) { recAddr := recAddr + 1 }
  for (c <- 0 until channels) {
    val adcWord = RegNext(io.adc(c).payload)
    recordMems(c).write(recWrAddr, adcWord, enable = recWrite)
  }
}
```

The one-cycle latency of the memory read is matched by registering `fire` once before the mux; the
DAC word is zero when not firing so the output is quiet between pulses. LED c toggles every time
channel c starts (c < 8).

### 4.5 Block design (`fpga/script/SimpleAwg.tcl`, `utils/Rfdc.tcl`, `utils/RfdcConfig.tcl`)

Three new cells on top of step 2:

- `clk_ifc`, a second module reference (`ClockInterface`, in `VivadoHelper.scala`): `IBUFGDS` +
  `BUFG` turning the LVDS board clock into `dspClk`, and the CLK104 SYSREF into `user_sysref`. Its
  input pairs are `diff_clock` interfaces, so the block design ports `dspClk` and `user_sysref`
  become the wrapper pins `dspClk_clk_p/n`, `user_sysref_clk_p/n` named in `zcu216-rf.xdc`.
- `dsp_rst`, a second `proc_sys_reset` in the `dspClk` domain, feeding `Top/dspRst` and the
  converter's stream resets.
- `rfdc`, the RF Data Converter (`usp_rf_data_converter:2.6`), configured with the 280-line property
  list copied verbatim from the RISC-Q / agentic-rv-dev build: all four DAC tiles at 8 GSPS with no
  interpolation (256-bit stream words), all four ADC tiles at 2 GSPS with no decimation (64-bit
  words), tile 2 of each kind taking the 500 MHz reference from the board (`dac_clk`, `adc_clk`) and
  distributing it. The 32 stream connections are a four-line loop: channel i of our module is tile
  i/4, slice i%4. All eight stream clocks are `dspClk`; the converter's own control registers hang
  off a second SmartConnect master on `pl_clk0`, with Vivado picking their address
  (`assign_bd_address` with no arguments).

`zcu216-rf.xdc` adds the LVDS pins, `create_clock -period 2.000` on `dspClk_clk_p` and the converter
reference clocks, and the asynchronous clock group. Build:

```sh
mill runMain vivado.tutorial.SimpleAwg       # writes SimpleAwg.v and ClockInterface.v
cd fpga/build && vivado -mode batch -source ../script/SimpleAwg.tcl
```

|--------------------------------------|--------------------------------------------------------------|
| `SimpleAwg/SimpleAwg_utilization.rpt`| 15 884 LUTs (3.7 %), 18 998 registers, 160 block RAM tiles (16 channels × (8 pulse + 2 record)) |
| `SimpleAwg/SimpleAwg_timing.rpt`     | all constraints met: WNS +0.153 ns on `dspClk_clk_p` (2 ns period), +0.774 ns on `clk_pl_0` |

### 4.6 On the board (`software/awg_demo.py`)

Order matters: the CLK104 module (LMK04828 + LMX2594) is programmed from Linux; until then there is
no `dspClk` and the converter tiles stay in reset. Clocks first, then the overlay, as in the RISC-Q
driver (`agentic-rv-dev/software/riscq/board/pynq_driver.py`, which additionally runs multi-tile
synchronisation and sets the Nyquist zones; this tutorial skips both).

```python
xrfclk.set_ref_clks(lmk_freq=500.25)          # 500 MHz PL clock + converter references
ol = pynq.Overlay("SimpleAwg.bit")
mmio = pynq.MMIO(0x8000_0000, 0x40_0000)

t = np.arange(16384) / 8e9                    # 2 us of a 125 MHz sine
load_pulse(0, (20000 * np.sin(2 * np.pi * 125e6 * t)).astype(np.int16))
play(0, 16384 // 16)                          # duration in 500 MHz cycles
while mmio.read(BUSY): pass
rx = read_record(LOOPBACK[0])                 # the ADC that DAC 0 is cabled to
```

Samples are int16, oldest in the lowest address: two per 32-bit bus word, 16 per DAC word, 4 per
ADC word (`np.int16 → view(np.uint32)` packs them). The `LOOPBACK` dictionary is the DAC-to-ADC
cabling of the test bench; adapt it to yours. Expect the 125 MHz burst in the record buffer a few
hundred nanoseconds after the start, attenuated by the cable.

## 5. Troubleshooting (things that went wrong while writing this)

- **`Bus Interface 'clk' does not have any bus interfaces associated with it` / `Clock interface
  'dspClk' has no FREQ_HZ parameter`**, then `validate_bd_design` complains that `S_AXI` sits on the
  wrong clock: the attribute is `X_INTERFACE_PARAMETER` (singular). With the plural spelling Vivado
  ignores it and associates every bus with the first clock port.
- **`FREQ_HZ does not match between /Top/clk(100000000) and /zynq_ps/pl_clk0(99999001)`**: the PS
  clock is 99.999 MHz, not 100 MHz. Do not state a frequency for clocks that come from the block
  design (`VivadoHelper.clockDomain` leaves it out); only the externally supplied `dspClk` carries
  `FREQ_HZ 500000000`.
- **`Cannot set the parameter FREQ_HZ on /clk_ifc/dspClk. It is read-only`**: once the RTL carries
  `FREQ_HZ`, do not also set it on the pin; set it on the block-design *port* instead.
- **`Reset pin ... is connected to asynchronous reset source /zynq_ps/pl_resetn0`**: feed IP resets
  from a `proc_sys_reset` output (`peripheral_aresetn`), not from `pl_resetn0` directly.
- **A memory became LUTs**: check the utilization report's block RAM line. SpinalHDL `Mem` with
  masked writes infers block RAM fine; `ram_style = "block"` is set on every memory as a hint.
- **Timing met by a few picoseconds at 500 MHz**: read the worst path in the timing report; if it
  starts or ends in a hard block (converter, PS), add a register on that side so the placer can
  put a flop next to it.
- **Nothing happens when software writes a register**: the block design address
  (`assign_bd_address`), the RTL base address and the Python offset must agree; a write to an
  undecoded address returns OKAY and does nothing.

- Give each `SimpleAwg` channel a start *time* compared against a free-running counter instead of

  flow, with the SoC packaged as an IP, is in `agentic-rv-dev/vivado-scripts/riscvsoc-bd`.
